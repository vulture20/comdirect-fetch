comdirect-fetch: Kategorien & Regeln

GitHub-Issue #13 · KONZEPT.md Abschnitt 12 · Änderungen wirken sich erst auf bestehende Umsätze aus, nachdem unten „Simulieren“ geprüft und „Jetzt anwenden“ ausgelöst wurde.

Nicht kategorisiert

Umsätze ohne echte Kategorisierung: gar keine Kategorie oder nur der Vorzeichen-Fallback (Sonstige Einnahme/Sonstige Ausgabe) - gute Kandidaten für eine neue Regel weiter unten. Einzelne Umsätze lassen sich hier auch direkt einer Kategorie zuordnen, ohne eine Regel anzulegen.

NameTyp

Die besonderen Kategorien Intern/Neutral, Sonstige Einnahme, Sonstige Ausgabe sind vor Umbenennen/Löschen geschützt (Vorzeichen-Fallback bzw. interne-Umbuchung-Erkennung hängen im Code fest an diesen Namen).

Regel gegen Echtdaten testen

Prüft nur, ob das Muster auf das jeweilige Feld passt (case-insensitive Teilstring) - unabhängig von Priorität und anderen Regeln. Schreibt nichts.

Simulation vor dem Übernehmen

Wendet den kompletten, aktuell gespeicherten Regelsatz auf alle nicht manuell kategorisierten Umsätze an - zeigt nur, was sich ändern würde, schreibt nichts. „Jetzt anwenden“ löst das bestehende POST /debug/recategorize aus.
